# 流水线

侧栏 **流水线** 把一类反复出现的协作固化成一条固定流程：你用一句话描述这类工作怎么流转，模型生成流程图，确认后保存；之后每次发起一件事项，它都沿着同一条流程由各个岗位依次处理，在需要你拍板的地方停下来等你。

## 概念

| 概念 | 说明 |
| --- | --- |
| 流水线 | 名称、需求说明、可选工作区（不绑定时岗位只能讨论）、流程定义 |
| 节点 | `TRIGGER` 触发（有且只有一个）、`AGENT` 岗位、`HUMAN` 人工环节、`END` 终点；共 3–12 个 |
| 岗位 | 名称、职责、模型、思考强度、审批模式；每个岗位是一次真实的 Agent 运行 |
| 连线 | 从一个节点到下一个节点；节点有多条出边时，每条边带一个不同的标签，表示该节点的结论 |
| 事项 | 一次触发产生一件事项，同一时刻只在一个节点上；保存触发时的流程快照，之后修改流程不影响它 |

终点只表示事项的最终状态（例如「自动合并」「打回作者」），不会执行任何命令。

## 预置流水线

首次启动带流水线的版本时（全新安装或升级），会预置一条「PR 流水线」，可以直接发起事项：

```text
新 PR → 门禁检查员 —通过→ 代码审查员 —通过→ 风险评估员 —低风险→ 可以合并
            └打回→ 打回作者     └需要修改→ 打回作者     └高风险→ 人工验收(你) —合并→ 可以合并
                                                                          └打回→ 打回作者
```

它没有绑定工作区，岗位只能根据事项说明讨论；要让岗位读代码，先点标题旁的编辑按钮绑定代码所在的工作区，并在发起事项时写明 PR 的分支、链接或改动说明。它就是一条普通流水线，可以修改或删除，删除后不会再次创建。

## 生成与修改

- **新建**：填写需求描述并选择模型，`POST /api/flows/design` 做一次无工具的模型调用，返回流程名称和定义，只预览、不保存；确认后再 `POST /api/flows`。
- **修改结构**：在流程图下方描述修改要求，同一接口带上当前定义重新生成，预览后保存。保留下来的岗位沿用原有的模型、思考强度和审批模式。
- **修改岗位**：点流程图里的节点，直接编辑名称、职责、模型、思考强度和审批模式。

模型的输出不符合规则时，会带上原因让它重新输出一次；仍不合规则返回错误。定义在生成和保存时都要通过校验：

- 有且只有一个触发节点，它只有一条出边、没有入边；至少一个岗位和一个终点，终点没有出边；
- 有多条出边的节点，每条边的标签非空且互不相同；节点不能连向自身；
- 每个节点都能从触发节点到达，并且都能走到某个终点（允许打回形成回环）。

## 流转

```text
发起事项 → 进入触发节点的下一个节点
  ├─ 岗位：在事项的隐藏会话里提交一次运行
  │    ├─ 运行完成，只有一条出边 → 走这条边
  │    ├─ 运行完成，多条出边 → 读取回复中最后一行「结论：X」，X 是某条边的标签则走这条边
  │    │                        否则事项等待你选择下一步
  │    └─ 运行失败、超时、被取消，或无法提交 → 事项等待你，可重试这个岗位或直接选择下一步
  ├─ 人工环节：事项等待你选择一条出边，可附带说明
  └─ 终点：事项结束
```

每件事项对应一个**隐藏会话**（`harness_session.flow_id` 非空），不出现在普通会话列表中；它的全部岗位都在这个会话里依次运行，所以后面的岗位能在对话历史里看到前面岗位的完整结论。每一步的提示词还会附上事项内容、此前的流转记录和你的说明。会话接口的改名、切换工作区、删除和提交对事项会话返回 409；读取仍然允许，「查看过程」就是打开这个会话，命令与文件修改的审批也在那里处理。事项的运行不参与长期记忆的自动提取。

一件事项最多经过 40 个节点，超过后以失败结束，避免打回形成的回环无限循环。停止事项会取消正在进行的运行。服务重启后，流转中的事项转为等待你处理（当前环节标记为中断），不会自动继续。

岗位运行中如果要你批准命令或外部工具调用、或向你提问，事项仍是 `RUNNING`，但概要里的 `pending` 会是 `APPROVAL`（待审批）或 `ANSWER`（待回答，两者都有时为前者）。这样的事项同样出现在「待你处理」里，点「去处理」进入事项会话批准或回答后继续流转。

事项状态：`RUNNING` 流转中、`WAITING` 待你处理、`COMPLETED` 已到达终点、`FAILED` 超过步数上限、`STOPPED` 已停止。

## 接口

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/flows` | `[{ flow, running, waiting, version }]`；`waiting` 包含运行中等审批或等回答的事项，`running` 不含；`version` 变化表示该流水线的视图可能已变化 |
| POST | `/api/flows/design` | `{ description, modelProfileId, reasoningEffort, definition }`，返回 `{ name, definition }`；`definition` 非空时表示在它之上修改 |
| POST | `/api/flows` | `{ name, description, workspaceId, definition }`，201 返回快照 |
| GET | `/api/flows/{id}` | 快照 `{ flow, items, version }`，`items` 为最近 100 件事项的概要 |
| POST | `/api/flows/{id}` | 修改流水线，`revision` 必须匹配；`definition` 为空时保留原定义 |
| POST | `/api/flows/{id}/delete` | 删除流水线、全部事项与其会话；有事项流转中时返回 409 |
| POST | `/api/flows/{id}/items` | `{ title, input }`，202 返回新事项 |
| GET | `/api/flow-items/waiting` | 所有流水线中等待你处理的事项，包含运行中等审批或等回答的事项 |
| GET | `/api/flow-items/{id}` | 事项详情 `{ item, input, sessionId, definition, steps, options, retryable }` |
| POST | `/api/flow-items/{id}/decide` | `{ label, note }`，为等待中的事项选择分支；只有一条出边时 `label` 可为空 |
| POST | `/api/flow-items/{id}/retry` | 重新运行等待中事项的当前岗位 |
| POST | `/api/flow-items/{id}/stop` | 停止流转中或等待中的事项 |
| POST | `/api/flow-items/{id}/delete` | 删除事项与其会话；流转中返回 409 |

页面每 2 秒读取一次列表和待办，`version` 变化时才重新读取快照和事项详情。

## 持久化

V31 预置「PR 流水线」一行数据。V30 新增 `harness_flow`（定义为 JSON 文本）、`harness_flow_item`、`harness_flow_step`，并为 `harness_session` 增加 `flow_id`（带索引）。步骤复制节点名称和类型，流程修改后历史记录不变；会话与运行的 id 不设外键。流水线写操作在会话存储的协调锁内完成；锁顺序为调度器 → 引擎 → 会话存储。事项的进度全部保存在数据库，调度器内存只记录进行中的运行属于哪件事项。

## 尚未支持

- 触发方式只有手动发起；定时触发、外部事件触发尚未实现。
- 不支持并行分支与汇合。
- 任务中心把事项的运行显示为普通任务；侧栏入口没有待办数量角标。
