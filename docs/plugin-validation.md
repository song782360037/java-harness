- SPI/Core：`RunExtension` 最小扩展契约，提交时捕获选择，首次模型请求前固定工具目录；复用现有执行循环、预算、幂等、取消和截止时间。

- Server：V11 增量迁移和本地管理/审批接口；沿用 Host/Origin 检查。
- Web：设置中的插件管理、命令选择、来源快照、审批卡和等待状态。
- 示例：纯 Markdown `java-review`；独立 Java SDK MCP `dependency-report`。后者为单独示例工程，不进入平台主进程 classpath。

完整格式和限制见 [插件使用与开发](plugins.md)。

本轮修改仅涉及引擎错误处理、外部调用审批与 MCP 发送边界、绑定读取/停用和信任身份、命令目录、Header 校验及插件设置页。没有新增数据库迁移。

1. `HarnessException` 的安全错误消息保留在 Run detail；未信任插件的真实引擎回归确认模型及网络均未调用。

## 配置恢复与连接故障隔离（2026-10-24）

本轮保持全局安装授权与不可变包内容，补充详情中的配置、凭据管理和已保存连接诊断；自定义扩展仍使用添加/编辑的同一表单。损坏凭据、缺失程序在列表显示原因并保留恢复入口。缺少必填配置的合法包保留为待配置状态；导入及选择失败回滚记录。保存与列表刷新分开反馈，重试刷新不会再次写入。

普通任务隔离准备和初始化阶段的连接故障，其他 MCP、Skill、本地工具继续可用；异常固定到 Run 快照并显示折叠提示。显式插件命令不能静默执行缺少连接的工作流。包校验、取消、撤销、工具数量限制和外部调用不可重放规则继续生效。Windows 支持 PATH 中的 `.cmd/.bat` 启动脚本，并在启动前拒绝不能可靠保持原义的批处理参数。

验证结果：
