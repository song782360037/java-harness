# 群聊

侧栏 **群聊** 用来模拟真实的群聊：你在群里提问题或提需求，多个 AI 成员按各自的职责分工协作，群里只展示每个成员的最终回复。

## 概念

| 概念 | 说明 |
| --- | --- |
| 群聊 | 名称、颜色、可选工作区（不绑定时只讨论）、隐藏主持人的模型与思考强度、每轮发言上限（1–50，默认 12） |
| 成员 | 昵称（1–20 字符，不含空格和 @，不能用"用户""系统"）、职责与工作侧重点、模型、思考强度、审批模式、是否参与 |
| 模板 | 内置项目经理、UI设计师、前端开发、后端开发、技术经理、测试工程师、运维工程师；添加时复制一份，之后修改不影响模板 |
| 轮次 | 一条用户消息开启一轮协作；协作中再发消息时，旧轮次标记为 SUPERSEDED，按新消息重新规划 |

每个成员对应一个**隐藏成员会话**（`harness_session.group_id` 非空），不出现在普通会话列表中；会话接口的改名、切换工作区、删除和提交对成员会话返回 409，只能通过群聊管理，读取（用于"查看过程"）仍然允许。成员每次发言就是这个会话中的一次普通顶层 Run，因此工具循环、子智能体、审批模式、文件修改审核、命令审批、插件和用量统计都沿用原有链路。群聊不绑定工作区时，成员会话也没有工作区，成员只能讨论。

## 调度

```text
用户消息 → 新轮次
  ├─ 消息里 @ 了成员 → 这些成员先发言（同一批最多 3 人并行）
  └─ 否则 → 隐藏主持人做一次无工具的模型调用，返回
       {"speakers":[{"member":"昵称","task":"…"}],"end":false}
成员 Run 结束
  ├─ COMPLETED：最终回答写入群聊；只回复 [PASS] 或空回复时不写入
  │   回复里 @ 了其他成员 → 被 @ 的成员排入下一批（优先于主持人）
  └─ 其他终态：写入一条系统消息（例如"后端开发 未完成发言（已停止）"）
一批成员全部结束 → 有排队成员则继续，否则再次询问主持人
```

协作中再发消息时，仍在发言的旧成员会说完，回复记在原轮次，但其中的 @ 不再在新轮次接力。一轮在以下情况结束：主持人返回 `end: true` 或空名单（COMPLETED）、达到每轮发言上限（COMPLETED，并附说明）、用户点击停止（STOPPED，取消正在发言的成员）、主持人输出无法解析或模型未配置（FAILED）。服务重启后，未结束的轮次标记为 INTERRUPTED，不会自动继续；成员运行由引擎的启动恢复标记为中断。

主持人调用使用群设置中的模型配置，受该配置的执行超时限制；它的用量不进入用量账本。

## 成员看到的上下文

成员运行通过 `RunExtension.context()` 拿到共享上下文。这个上下文**替代**成员会话自己的历史，作为 `<group_chat>` 块放在本次提示词前面，包含：

- 自己的昵称与职责、全部参与成员的名单与职责（因此成员知道该 @ 谁）；
- 群规：只代表自己发言、不复述、需要别人时 @ 昵称、没有新内容回复 `[PASS]`、修改需审核；
- 群聊记录：只包含用户、成员的最终发言和系统消息，不含任何人的工具调用过程。每条发言是一个 `<message role="user|member|system" author="…">` 块，role 和 author 由系统按存储的发言人标注；正文中任何大小写的 `<message`、`</message`、`<group_chat`、`</group_chat` 都会转义，成员回复不能伪造用户发言或提前结束记录。记录按 token 预算从最新往前保留：本轮用户消息始终保留，单条过长的发言被截断，而不是丢掉它之前的全部记录。头部（成员名单与职责）放不下时，成员运行以"上下文窗口不足"失败。

本次提示词是主持人分配的任务，或"某某在群聊中 @了你"。记录在提交时快照，同一批并行的成员看到的是同一份记录。群聊成员的运行不参与长期记忆的自动提取，但仍会召回已有记忆。

## 文件修改与审批

成员按各自的审批模式提出文件修改和命令。命令审批卡片显示在成员的"正在输入…"位置下方；文件修改卡片挂在对应发言下方。群里有成员正在发言时，不能应用或撤销任何成员的修改（`BUSY`），避免和进行中的修改冲突。并行成员针对同一文件的提案，应用时由已有的内容冲突检测拦截。

## 接口

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/group-templates` | 内置成员模板 |
| GET | `/api/groups` | `[{ group, members, busy }]`，按创建时间倒序 |
| POST | `/api/groups` | `{ name, color, workspaceId, hostProfileId, hostReasoningEffort, maxTurns, templates }`，201 返回快照 |
| GET | `/api/groups/{id}` | 快照 `{ group, members, messages, round, busy, runs, version }`；runs 是正在发言的运行和消息关联的运行，`activity` 变化时刷新卡片 |
| POST | `/api/groups/{id}` | 修改群设置，revision 必须匹配；协作中不能切换工作区 |
| POST | `/api/groups/{id}/delete` | 删除群聊、成员会话与记录；协作中返回 409 |
| POST | `/api/groups/{id}/members` | 新增成员；`template` 非空时，未填写的字段取模板值 |
| POST | `/api/groups/{id}/members/{memberId}` | 修改成员；模型、强度和审批模式从下一次发言开始生效 |
| POST | `/api/groups/{id}/members/{memberId}/delete` | 移除成员与其会话，历史发言保留作者名；成员正在发言时返回 409 |
| POST | `/api/groups/{id}/messages` | `{ requestId, content }`，202；同一 requestId 重试返回原消息 |
| POST | `/api/groups/{id}/stop` | 停止本轮协作 |
| GET | `/api/groups/{id}/events` | SSE，事件名 `group-event`，数据为 `{ version }`（字符串，群序号与成员会话可见事件序号拼接）；只表示"群聊视图可能变化"，客户端收到后重新读取快照 |

## 持久化

V23 新增 `harness_group`、`harness_group_member`、`harness_group_round`、`harness_group_message`，为 `harness_session` 增加 `group_id`（带索引），并为 `harness_event(session_id, event_type, seq)` 建索引，供群聊视图轮询。消息复制作者昵称，成员被移除后历史发言仍可显示；`run_id` 不设外键。群聊写操作在会话存储的协调锁内完成；锁顺序为调度器 → 引擎 → 会话存储，存储锁内不回调调度器。引擎在运行结束后（即使结算失败）通知调度器；调度器内部出错时本轮以 FAILED 结束并停止仍在发言的成员，不会一直显示协作中。删除群聊或切换工作区前的忙碌检查与写入之间存在很小的时间窗，在此期间开始的一轮会在下一步因群聊已删除而自行结束。
